# Claim Code gift L2 proof — single-unit source authority

**Status:** Implemented for certification. **NO MERGE / NO PRODUCTION.**

This stacked proof [DS PR #343](https://github.com/jan2xo/bke-digital-solutions/pull/343) is based on the exact-source-certifed [DS PR #341](https://github.com/jan2xo/bke-digital-solutions/pull/341) (head `6867b1eee0044abfbd4f5f7bfcad7fa59145e38e`).

## Verified behavior and source ownership

A **synthetic disposable** PAID/CLAIM_CODE gift Order and one-unit OrderItem, belonging to purchaser Account A, issue a matching persisted disposable ClaimCode fixture with HMAC material generated by the *real* `claim-code-material` code. The actual server `consumeClaimCode` is invoked against disposable PostgreSQL and must issue Account B's License and Entitlement in the same serializable redemption transaction. The actual [DS L2 source reader](https://github.com/jan2xo/bke-digital-solutions/pull/341) must return the bound recipient right only; purchaser A and unrelated C must not receive ownership or a license. It must reject replay, a pending/unpaid gift source, tampered ClaimCode claimed target/purchaser/product source and terminally revoked Entitlement.

The redemption source now refuses to treat the mere presence of an AVAILABLE claim as payment proof: requires an actually **PAID** Order, non-null paidAt, `CLAIM_CODE` fulfillmentMode, exact purchaser-account and OrderItem/product/edition/plan lineage, quantity exactly one and ClaimCode unit index zero. A failed source check returns `INVALID_CODE` **before** any Entitlement/License issuance. The L2 evidence query additionally binds the claimed ClaimCode's order and purchaser to the same PAID source Order as the recipient License.

**Important limitation:** this verifies real redemption, not the external payment webhook or real provider. The test inserts a synthetic ClaimCode row using real hash/encryption materials so it can certify redemption without production payment/delivery keys. The source-protected `issueClaimCodes` function is unchanged; issuance has separate existing tests. There is *no real Agent access token* in the test and its policy accept result uses a clearly synthetic installability context; live Agent session and published product release are still separately owned.

## Quantity and security

`License.orderItemId` remains UNIQUE, so multiple gifts under one item are not certified. The redemption guard denies `OrderItem.quantity > 1` and nonzero ClaimCode unit index rather than producing an over-broad license from `maxSeats = item.quantity * maxSeats`. Multi-unit gifting needs a separately owned licensing/commerce schema, migration and CI intent. **Do not weaken these constraints or claim broader readiness.**

**Minimum complete exact-head graph:** `pr + core + commerce + entitlements + licensing + catalog + native-account`. `core` owns all disposable DB runtime tests. Not required: Payments/provider canaries, production, Agent/Launcher/Render Dock binaries, Windows/UTM, installer, JWS package/release, real provider emails. Trigger only trusted `/certify` PR comment.
