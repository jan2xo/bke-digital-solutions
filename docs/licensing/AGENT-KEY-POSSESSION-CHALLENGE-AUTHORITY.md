## Implemented source and exact trust contract

- `prisma/migrations/20261111130000_agent_lease_key_proof/migration.sql` creates append-history AgentLeaseKeyRegistration and AgentLeaseKeyChallenge tables, each FK-bound to an actual AgentAccountSession; account and user FKs bind the registration to DS authority. A partial unique index permits only one ACTIVE or PENDING key per session. Registration status transitions PENDING→ACTIVE (after cryptographic proof)→REVOKED (terminal); revocation has required timestamps and audit evidence. Private key material is never stored in DS.
- `apps/web/agent-sessions/agent-key-proof-authority.ts`: verifies existing Agent bearer token via `authenticateAgentAccessToken` **before** touching key/challenge rows. Accepts only canonical Ed25519 SPKI PEM and derives SHA256 SPKI DER thumbprint. Enrollment requires an externally originated Agent public key and creates a PENDING registration plus CSPRNG 32-byte ENROLL challenge.
- The exact bytes signed are domain-separated UTF-8: `bke.agent-key-proof.v1\n<purpose>\n<challengeId>\n<registrationId>\n<sessionId>\n<accountId>\n<userId>\n<deviceId>\n<productId-or-minus>\n<action-or-minus>\n<nonceBase64url>`. Server stores SHA256(message), not the nonce; challenge expires in 30 seconds and must be returned verbatim by Agent. LEASE challenges bind both product and OPEN/USE action in addition to Agent session/device/account/user.
- `verifyAgentKeyChallenge` locks the challenge+registration row, checks authenticated identity and current lifecycle, **atomically consumes the nonce before** verifying a canonical Ed25519 64-byte signature with `node:crypto.verify`. Wrong signatures burn the challenge; no second attempt can reuse it. ENROLL proof marks key ACTIVE and emits scoped audit record. LEASE proof produces a **server-created internal Symbol-branded** VerifiedAgentLeaseProof object; serialization drops the brand and caller-supplied `proofState=VERIFIED` cannot mint it.
- `prepareLeaseClaimsWithVerifiedKey` rechecks exact product/action/session/account/user binding and makes each verified proof one-shot in process; it delegates to the already-certified #344 five-minute rights-limited unsigned claims composer. Any mismatch or reuse fails closed. **Future actual signing MUST recheck key revocation in the same server-side SERIALIZABLE transaction at issuance; an earlier proof object is not independent authority after revocation.**
- `revokeAgentLeaseKey` requires original authenticated session and atomically terminates the registration and unspent challenges; repeat revocation is idempotent. Enrollment and revocation are separately audited.
- `tests/integration/agent-key-possession-authority.test.ts` uses **real disposable PostgreSQL**, actual synthetic but internally consistent consumed Agent sessions, real `hashAgentAccessToken`, real Ed25519 keypairs/signatures and serializable transactions. Tests enforce owner identity, 30s/one-use, invalid signatures burned, foreign account/token isolation, exact product/action, non-serializable proof, source composer and terminal revocation. `tests/agent-key-possession-authority.test.ts` contains hermetic structural guards.
